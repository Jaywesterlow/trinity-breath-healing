<objective>
Fix two Werkwijze section bugs on mobile (<1024px):

1. Neighbour-card peek: `.werkwijze__cards` gap is a flat 64px while the centering `padding-inline` grows with viewport width, so past ~410px the padding exceeds the gap and the next card's edge becomes visible. Make the gap scale with the same calc so it always exceeds the padding by a buffer.
2. Add JS scroll-jacking: while the section is in view on mobile, vertical scroll drives horizontal translation of the card track (continuous 1:1, not per-card snapping) via `position: sticky` + rAF-throttled transform. Once the last card is reached the page resumes normal vertical scroll. Direct swipe on the card track still works as an escape hatch. `prefers-reduced-motion: reduce` disables all of this and restores exactly today's behavior. Desktop (>=1024px) is untouched.

Purpose: Close a visual bug (card peek) affecting common phone widths, and implement the locked UX decision from CONTEXT.md for a more app-like mobile "how it works" reveal, without harming SEO/AEO (all cards stay in initial HTML) or accessibility (no focus trapping).

Output: Updated `src/lib/components/global/Werkwijze.svelte` — markup gets a pin/sticky wrapper (inert unless JS activates it), styles get the corrected gap calc plus scroll-jack CSS scoped to a JS-toggled class, script gets an `onMount` effect managing the scroll-jack lifecycle.
</objective>

    **Script (Svelte 5 runes):** Import `onMount` from `'svelte'`. Add state: `let pinEl: HTMLDivElement | null = $state(null);`, `let cardsEl: HTMLUListElement | null = $state(null);`, `let scrolljack = $state(false);`, `let pinHeight = $state(0);`, `let offset = $state(0);`. Add module-level (non-reactive) `let maxOffset = 0;`, `let ticking = false;`.

    Implement `computeMaxOffset()`: returns `Math.max(0, cardsEl.scrollWidth - cardsEl.clientWidth)` (guard `cardsEl` null → 0).

    Implement `updateOffset()`: reads `pinEl.getBoundingClientRect()`, computes `scrolled = Math.max(0, -rect.top)`, sets `offset = Math.min(scrolled, maxOffset)` (guard `pinEl` null → return).

    Implement `onScroll()`: rAF-throttle via the `ticking` flag — if `ticking` is true, return; else set `ticking = true`, call `requestAnimationFrame(() => { updateOffset(); ticking = false; })`. Register with `{ passive: true }`.

    Implement `onResize()`: if `scrolljack` is true, recompute `maxOffset = computeMaxOffset()`, `pinHeight = window.innerHeight + maxOffset`, call `updateOffset()`.

    Implement `enable()`: set `maxOffset = computeMaxOffset()`, `pinHeight = window.innerHeight + maxOffset`, `scrolljack = true`, call `updateOffset()`, `window.addEventListener('scroll', onScroll, { passive: true })`, `window.addEventListener('resize', onResize)`.

    Implement `disable()`: set `scrolljack = false`, `offset = 0`, remove the scroll and resize listeners added in `enable()`.

    In `onMount`: create `const mobileMq = window.matchMedia('(max-width: 1023.98px)')` and `const motionMq = window.matchMedia('(prefers-reduced-motion: reduce)')`. Define `evaluate()` that computes `shouldEnable = mobileMq.matches && !motionMq.matches` and calls `enable()`/`disable()` only on state transitions (avoid re-enabling an already-enabled state). Call `evaluate()` once immediately, then `mobileMq.addEventListener('change', evaluate)` and `motionMq.addEventListener('change', evaluate)`. Return a cleanup function from `onMount` that removes both `change` listeners and calls `disable()` unconditionally (safe no-op if already disabled).

    **Styles:** Add `.werkwijze__pin { position: relative; }` (no-op by default — height stays `auto` since no inline height is applied unless active). Bind `style:height={scrolljack ? pinHeight + 'px' : 'auto'}` on the `.werkwijze__pin` div in markup. Add `.werkwijze--scrolljack .werkwijze__sticky { position: sticky; top: 0; }` (default `.werkwijze__sticky` has no positioning — plain block, matches today's flow layout when inactive). Bind `style:transform={scrolljack ? \`translateX(-${offset}px)\` : ''}` on the `.werkwijze__cards` `&lt;ul&gt;` — this is additive to (not a replacement of) its existing native `overflow-x: auto` + `scroll-snap-type: x mandatory`, so a direct swipe on the track still moves it independently as the escape hatch. Do not add `overflow: hidden` to `.werkwijze__sticky` — rely on the existing `.werkwijze { overflow: hidden; }` (section-level, already present) to clip horizontal overrun; do not change that existing rule. Do not add any `@media (min-width: 1024px)` overrides for the new pin/sticky rules — the `scrolljack` class is only ever applied when `mobileMq.matches` is true, so desktop is unaffected by construction; do not gate the CSS with an additional width media query (would be redundant and risks drifting out of sync with the JS breakpoint).
