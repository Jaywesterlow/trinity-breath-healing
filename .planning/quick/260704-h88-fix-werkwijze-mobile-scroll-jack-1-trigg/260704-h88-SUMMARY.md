# Quick Task 260704-h88: Fix Werkwijze Mobile Scroll-Jack Summary

**Rebuilt the mobile scroll-jack mechanism in Werkwijze.svelte from a scroll-driven transform illusion (Pattern A) to a true wheel/touch/keydown scroll-lock state machine (Pattern B) triggered by an IntersectionObserver at the viewport's vertical middle.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 2/2 auto tasks completed; 1 checkpoint:human-verify task reached and returned (not executable by this agent)
- **Files modified:** 2 (1 rewritten, 1 created)

## Accomplishments

- Removed the old `pinHeight`/`ticking`/`updateOffset`/`onScroll` scroll-event-polling implementation entirely from `Werkwijze.svelte`.
- Implemented the 3-state machine (`disabled -> idle-before -> locked -> idle-after`) exactly per plan: `IntersectionObserver` trigger, `wheel`/`touchstart`/`touchmove`/`keydown` lock listeners with `{ passive: false }` + `preventDefault()`, shared `applyDelta()` boundary/clamp/release logic, `data-scroll-phase` attribute for observability.
- Added conditional `.werkwijze--locked .werkwijze__cards { overflow-x: hidden; touch-action: none; }` and a `:global(html.werkwijze-locked)` `overscroll-behavior: none` backstop, without touching the existing default `.werkwijze__cards` rule or either desktop `@media` block.
- Preserved the card-peek gap-fix CSS from 260704-fj7 untouched, as required.
- Wrote a 5-case Playwright integration spec (`tests/integration/werkwijze-scrolljack.spec.ts`) covering mid-viewport trigger, scrollY-freeze while locked, forward auto-unlock at the last card, `prefers-reduced-motion: reduce` full bypass, and Tab-focus-not-trapped.

## Decisions Made

- Kept `position: sticky` on `.werkwijze__sticky` (did not switch to `position: fixed` + spacer) — RESEARCH.md Open Question #2 recommended trying sticky first since scrollY never advances during the lock; the human-verify checkpoint (item 3 in `how-to-verify`) asks the user to confirm there's no jump on lock-engage, which would indicate sticky needs to be dropped in a follow-up.
- Wheel sensitivity is 1:1 pixel mapping after `deltaMode` normalization (line mode ×16, page mode ×innerHeight) — no additional multiplier. This is the RESEARCH.md-flagged tunable constant (Open Question #1); the checkpoint asks the user to flag if it feels too fast/slow.
- Touch delta is direct 1:1 finger-tracking (`lastTouchY - currentY`), no multiplier, per plan Task 1 spec.
- Symmetric bidirectional lock: `handleIntersect` re-engages on any crossing while `phase !== 'locked'` (covers both `idle-before` and `idle-after`), so scrolling back up into the section from below re-engages the lock and releases backward at the first card — implemented as specified.
