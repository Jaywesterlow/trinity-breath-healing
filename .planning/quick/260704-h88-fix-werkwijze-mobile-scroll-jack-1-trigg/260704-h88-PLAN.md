<objective>
Rebuild the mobile scroll-jack mechanism in `src/lib/components/global/Werkwijze.svelte` — this is a full replacement of the internal mechanism, not a patch. The current build (quick task 260704-fj7) implements **Pattern A** ("scroll-driven pin"): a passive `scroll` listener + rAF-throttled `getBoundingClientRect()` polling that derives `translateX` from native scroll position, with the pin wrapper's height padded by `maxOffset` so the trick works. This is architecturally wrong for what the user now wants: a genuine scroll-lock that engages precisely when the section reaches the viewport's vertical middle (not top-edge), fully freezes vertical scroll (not a transform illusion riding on top of continuing scroll), and releases cleanly once the last card is reached.

Rebuild as a 3-state machine (`idle-before -> locked -> idle-after`) per RESEARCH.md's Pattern B recommendation:
1. **Trigger:** `IntersectionObserver` with `rootMargin: "-50% 0px -50% 0px"` on the pin wrapper — replaces all scroll-event/`getBoundingClientRect` polling for trigger detection.
2. **Lock:** `wheel`/`touchmove`/`keydown` listeners with `{ passive: false }` + `preventDefault()`, manually accumulating delta into a clamped `offset` (0..maxOffset) driving `translateX`. `overscroll-behavior:none` (via a documentElement class) and `body.style.overflow = 'hidden'` are defense-in-depth backstops only, not the primary mechanism.
3. **Root cause fix:** `.werkwijze__cards`'s unconditional `overflow-x: auto` fights the JS transform via native touch-scroll — must become conditionally `overflow-x: hidden` (+ `touch-action: none`) only while locked, reverting to `auto` otherwise so the swipe fallback outside the lock still works.
4. **Unlock:** once accumulated delta reaches the last card (or, symmetrically, back to the first card), stop calling `preventDefault()` on the boundary-crossing event so it falls through to native scroll, and stop attaching lock listeners.
5. **Simplification:** since native `scrollY` never advances during the lock, the old `pinHeight = innerHeight + maxOffset` padding trick is removed — no extra pin-wrapper height is needed.
6. Non-negotiable carryovers unchanged: `prefers-reduced-motion: reduce` disables everything; desktop (>=1024px) untouched via the existing `matchMedia('(max-width: 1023.98px)')` gate; all 3 cards stay in server-rendered initial HTML unconditionally; no keyboard focus trapping (Tab/Shift+Tab never intercepted); the card-peek gap fix CSS from 260704-fj7 stays untouched.

Purpose: Deliver a scroll-lock that actually works (current build "is not working properly at all" per user report) using the architecturally correct pattern confirmed by research, while preserving accessibility (no focus trap, reduced-motion escape hatch) and SEO/AEO (all cards always in initial HTML).

Output: Rebuilt `src/lib/components/global/Werkwijze.svelte` (script + markup + styles), new `tests/integration/werkwijze-scrolljack.spec.ts` Playwright spec, and a human-verify checkpoint confirming real-device/browser feel.
</objective>
